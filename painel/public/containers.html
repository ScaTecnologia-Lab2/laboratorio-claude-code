Containers (Docker)

Cada parte da aplicação roda isolada dentro do seu próprio container. Aqui você vê quais estão de pé, quanto consomem e o que estão escrevendo nos logs.

O que você está vendo nesta tela

Esta lista vem do comando docker ps -a (estado) e docker stats (consumo), atualizada a cada 5 segundos.

Container
Um processo isolado, empacotado com tudo que precisa para rodar (programa, bibliotecas, configuração). É como uma "mini máquina" leve. Ele é criado a partir de uma imagem (a receita pronta, por exemplo postgres:16-alpine).
Os 4 containers do LabSystem
frontend (nginx: entrega as páginas e repassa a API) → backend (Node.js: regras do sistema e login) → fornecedores (Python/Flask) e postgres (o banco de dados). Eles são definidos no docker-compose.yml.
Situação
Saudável / Rodando está tudo certo. Iniciando ainda está ligando. Reiniciando o programa dentro do container termina com erro e o Docker o liga de novo, em ciclo: abra os Logs para ver o motivo. Parado foi desligado.
"Saudável" (healthcheck)
Alguns containers têm um teste automático (ex.: o backend responde em /health). Se o teste falha, o Docker marca como "com problema".
Portas
127.0.0.1:5151->5432/tcp significa: a porta 5151 do seu computador leva à porta 5432 dentro do container. O prefixo 127.0.0.1 quer dizer "só este computador consegue acessar".
CPU e Memória
Quanto do processador e da RAM o container está usando agora. Um container parado não consome nada.

Logs de

Log é o "diário" do programa: tudo que ele escreve na tela. Quando algo dá errado, a explicação costuma estar nas últimas linhas. A hora vem no começo de cada linha.
